# Application and role contract

This records the implemented API boundary for the three PWAs and the planned Driver app. The published route schema is [`openapi/v1.json`](openapi/v1.json); this table adds authorization and product meaning that OpenAPI does not express. All listed operational requests require a backend session and the server-derived jurisdiction. A visible button or a role in a browser response is never the authorization decision.

| Application / role | Implemented entry and endpoints | Server permission and scope | Still required for the approved journey |
|---|---|---|---|
| Control / `dispatcher` | `/control/`; `GET /v1/corridors`, `GET /v1/corridors/{corridor_id}/state`, `GET /v1/corridors/{corridor_id}/capabilities`, `GET /v1/mission-assignees`, `POST /v1/missions`, `GET /v1/missions`, `GET /v1/missions/{mission_id}`, `POST /v1/missions/{mission_id}/start`, `POST /v1/missions/{mission_id}/complete`, `POST /v1/routes/compare` | `read_corridor_state`, `create_mission`, `view_mission` (owner), `compare_routes` in the assigned jurisdiction | Vehicle/driver assignment, selected-route binding, mission-impact and reroute approval, delivery confirmation |
| Control / `regional_viewer` | `/control/`; corridor catalog, state, capabilities, maps and source/model read views | `read_corridor_state` in the assigned jurisdiction; no mission mutation | A read-only operational overview after verified corridor data is imported |
| Authority / `reviewer` | `/authority/`; corridor read; `GET /v1/field-reports`, `POST /v1/reviews/{evidence_id}` | `review_evidence` in the assigned jurisdiction | Clarification reply and conflicting-evidence resolution |
| Authority / `district_officer` | `/authority/`; corridor read; `GET/POST /v1/status-decisions` | `publish_status` requires an active `status_authority` grant for the jurisdiction | Alerts and decision-to-mission impact |
| Authority / `system_admin` | `/authority/`; `GET /v1/admin/corridors`, `GET/POST /v1/admin/users`, `POST /v1/admin/users/{actor_id}/roles`, story administration | `manage_users` in the assigned jurisdiction; no `read_corridor_state` or operational approval | Configuration and audit access that remains separate from road decisions |
| Field / `field_reporter` | `/field/`; corridor read; `POST/GET /v1/field-reports`, report media endpoints, `GET /v1/missions`, `GET /v1/missions/{mission_id}`, `POST /v1/missions/{mission_id}/start`, `/complete`, `/positions` | `create_field_report`, `upload_own_media`, `submit_gps`; mission reads and actions require an explicit assignment | Offline photo capture, clarification responses, alert inbox |
| Driver / no role yet | No Android app, driver role, acceptance endpoint, downloaded trip, or route-change acknowledgment | No implicit access through `field_reporter` or `dispatcher` | Define and test driver identity, assignment, acceptance, trip storage, location consent, and delivery proof before enabling Driver |

`GET /v1/auth/session` and `POST /v1/auth/login`, `/v1/auth/logout` are shared identity endpoints. The frontend uses same-origin, HTTP-only session cookies; the backend rechecks persisted account roles, jurisdiction assignments, expiry, and revocation on requests. Tests in `tests/contracts/test_api.py` and `tests/contracts/test_login.py` cover those session boundaries. `tests/test_operations.py` covers wrong jurisdiction, wrong role, and same-jurisdiction unassigned mission access. The current mission assignee is a field reporter, not a driver; route comparisons are unverified baselines, not truck-safe recommendations.
